02

Experiment Procedure

The experiment uses a controlled retention workload so hint effects can be compared under the same distractor pressure.

Method Summary
  • Built a synthetic A → distractors → A replay retention workload.
  • Instrumented Dynamo and SGLang for direct worker attribution.
  • Increased distractor count step by step to raise cache pressure.
  • Compared a no-hint control against a protected-hint run.
  • Injected frontend hints only into the protected run.
  • Recorded first-request, replay, latency, and cache metrics at each point.

03

Direct Attribution

We instrumented the path so we can trace a hint from the frontend to worker-side cache behavior.

Step 1

Frontend sent hint

The request carries the hint payload and probe identity into the runtime path.

Step 2

Worker received hint

The worker-side logs tell us whether the hint object actually arrived.

Step 3

Hint could affect behavior

We check that the system was ready to use the hint and whether replay stayed cached.

Takeaway

A valid attribution needs all three: sent, received, and runtime-ready.

04

Retention Probe Design

Each sweep run sends the same protected prompt twice, with a configurable number of unique distractors in between. The control and protected rows are then compared side by side.

Workload Pattern

A → distractors → A replay

A first populate cache
→
D1 … Dn competing requests
→
A replay measure reuse
control: none
protected: high-priority
Control Run (No special protection)

The control row sends A without a protective priority hint. Its replay behavior tells us what ordinary retention looks like under the chosen policy.

Protected Run (Same prompt with high priority hint attached)

The protected row sends the same A request with a stronger priority profile. If the runtime respects it, replay A should remain warm deeper into the distractor sweep.

05

Latency Response to Increasing Distractors

  • Dashed lines are the initial A request. Solid lines are the replay A request after distractor pressure.
  • For the control run (blue line), replay latency spikes once distractor pressure is high enough, suggesting cache reuse has started to break down.
  • For the hinted run (green line), replay latency stays closer to its baseline for longer, suggesting better cache retention under pressure.
  • The orange line shows the first A request, giving the baseline latency before distractor pressure affects replay.

Cached Tokens Under Increasing Distractors
