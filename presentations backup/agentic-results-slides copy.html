Execution Setup: Core Components

A four-layer workflow that turns benchmark tasks into observable agent runs.

SWE-bench Tasks
→
Deep Agents Workflow
→
Dynamo Runtime
→
SGLang Inference
SWE-bench
Provides realistic software-engineering tasks and expected fixes.
Deep Agents
Orchestrates planning, execution, patch generation, and review.
Dynamo
Packages requests and records runtime and tool observability.
SGLang
Executes inference and returns tool-call and response outputs.
Together, these components let us trace how a task moves from benchmark input to agent behavior.
Slide 2

Current Progress

The workflow is now observable end to end, and some runs complete through patch creation.

What Now Works

  • Patch creation observed: Some tasks now complete through to actual patch creation.
  • Multi-phase flow visible: Runs now follow planning, execution, patch generation, and review.
  • Execution is multi-step: The execution phase now moves through multiple logical steps instead of a single-shot attempt.
  • Tool use confirmed: Tool activity is visible by phase, so we can verify what the workflow actually did.

What We Are Improving

  • Completion quality: Improve performance across more repos and task types.
  • Execution depth: Reduce inspection-heavy runs that stop short of meaningful edits.
  • Model capability: Test a larger model to improve reasoning and patch quality.

Bottom line: the workflow is now visible; model capability is the next major lever.

What Is Already Working

  • Multi-phase execution is now real and observable, not just conceptual.
  • Every run shows tool-call evidence, and 16 runs already use write-oriented tools.
  • A subset of runs now completes through patch creation, demonstrating true end-to-end workflow closure.

This means the orchestration stack can now produce inspectable evidence across the full task lifecycle.

What Needs The Next Push

  • Patch-producing runs are currently concentrated in one repo family, so generality is still uneven.
  • Many runs remain inspection-heavy, especially outside the strongest-performing task cases.
  • The next lever is a larger model, measured against patch rate, repo coverage, and quality of final diffs.

Bottom line: the workflow is now observable end to end; the next step is improving task-solving capability.
